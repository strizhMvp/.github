# Независимое ревью СТРИЖ

Решение владельца от 23.11.2026: Claude/Anthropic больше не используются.
Критерии прежнего ревью сохранены здесь; PR проверяется в рабочем процессе
Orca/Codex, а не фиктивной AI-проверкой GitHub Actions.

## До ревью

- Прочитать задачу из `Closes <repo>#N`, исходный запрос и критерии приёмки.
- Проверять фактический diff относительно целевой ветки и затронутых потребителей.
- `main` — версия банка. Новые разработки, включая актуализацию, остаются в `dev`.
  Хотфикс переносится отдельными PR; полный merge `dev` в `main` требует согласования релиза.
- Применимые существующие локальные проверки должны пройти; команды, фактические
  результаты, проверенные SHA и ограничения публикуются в PR. Для документации не
  требуется весь набор lint/type/tests/build. Размер оценивается локально относительно
  целевой ветки: ориентир 400, запрет выше 800 строк без согласованного `large-pr`,
  lock-файлы исключаются. Зелёные Actions и size-job больше не являются merge gate.

## Что проверять

1. **Безопасность:** секреты и токены в коде/логах; SQL/JQL/CQL/shell-инъекции;
   авторизацию и изоляцию команд; персональные данные; десериализацию.
2. **Корректность:** реальные сценарии, ошибки и таймауты Jira/Xray/Confluence/LLM;
   гонки, lifecycle, потерю данных, идемпотентность повторов. Тесты в Jira
   архивируются, а не удаляются вместе со связями с прогонами.
3. **Совместимость:** API-контракты и всех потребителей, миграции и откат.
4. **Объём:** одна задача — небольшой PR; без посторонних рефакторингов/фичей;
   автоматически генерируемые блоки README не редактируются вручную.
5. **Проверки:** новое поведение доказано релевантными тестами/сценарием;
   наличие теста само по себе не доказывает, что он ловит ошибку.
6. **Документацию:** отсутствие ложных обещаний; новые переменные описаны в
   `.env.example`; локальные проверки не выдаются за доказательство установки.

Сообщать только проблемы, подтверждённые кодом или результатом проверки.
Без похвалы, стилистических замечаний и пересказа diff.

## Вердикт

- **P0:** блокер, потеря данных или критическая безопасность.
- **P1:** воспроизводимый баг; исправить до мержа.
- **P2:** поддержанное замечание; решение автора фиксируется явно.
- **P3:** мелочь; не превращать её в обязательное расширение задачи.

Замечание содержит точный файл/строку, краткий заголовок, сценарий и последствия.
Итоговый комментарий PR: `pass`, `needs_changes` или `blocked`, уровни замечаний,
что проверено, команды и фактические результаты, непроверенные live-границы.
Результат независимого технического ревью и отдельной проверки полноты исходного
запроса публикуется в PR; на оба результата нужны публичные ссылки и точный
проверенный head SHA. Команды, зависимости/соседние SHA и ограничения должны позволять
отличить фактическую проверку от предположения. Изменения после ревью требуют
повторной проверки затронутой части на новом head SHA; неизменённые доказательства
переиспользуются, старый вердикт не переносится вслепую.
До мержа оба независимых результата должны быть `pass`; `needs_changes` или `blocked`
оставляют соответствующий gate открытым.

По умолчанию нужен аппрув второго разработчика; локальный self-check и независимые
вердикты сами по себе его не заменяют. Исключение владельца вместо формального
GitHub-аппрува действует только для существующих dev PR `strizh-shared#41`,
`strizh-auth-service#78`, `strizh-monitoring-service#23`, `strizh-admin-service#41`,
`strizh-generation-service#212`, `strizh-integration-service#69`,
`strizh-pipeline-service#28`; актуальные два независимых результата в PR обязательны.
Новые frontend/infra dev PR, общий `.github` main PR и последующие delivery main PR
требуют обычного аппрува либо нового явного адресного решения владельца.
Разрешение production effect не является исключением из approval/release/ИБ.

Существующие локальные pytest/ruff/mypy/tenant guard и live golden/eval команды
сохранены в [CONTRIBUTING.md](CONTRIBUTING.md). Не добавлять runner или фиктивный
успех. Снятие CI не исправляет billing и не доказывает deploy/live-качество.
Действующие deploy и tracker не отключаются. Блокирующий required check фиксируется
как точный блокер без обхода; 403 protection/rulesets не означает отсутствия защиты.

В Actions не настроен новый AI-провайдер. Авторизация чата не означает доступ SDK
или workflow: не добавлять предполагаемые токены, тихие fallback-и или команды
`@codex`. Секреты, старые настройки аккаунта и облачная история не переносятся.
